# Pool management — implementation plan

Design: [pool-design.md](pool-design.md) · Decisions: [pool-decisions.md](pool-decisions.md) · Order: [operations-plan.md](operations-plan.md)

- [ ] **POOL1 — More disks than the inline descriptor slots.** `PoolManager` rejects pools beyond the inline limit with `PoolError::DiskOverflowUnsupported` (`crates/pool/src/pool.rs`); route the extra descriptors through the `disks_overflow` tree. Acceptance: a pool with more disks than the inline slots creates, reopens and lists every disk.
- [ ] **POOL2 — Ontology-driven placement end to end.** An ontology rule attached to a tag (for example `archive` implies cold tier) moves matching objects without a separate user action. Prerequisites: [BLOB1](blob-implementation-plan.md), [RECONCILE5](reconcile-implementation-plan.md), [TOOLING3](tooling-implementation-plan.md), POOL4. [Acceptance scenario](operations-design.md#acceptance-scenarios).
- [ ] **POOL3 — Pool state through the root pointer.** Locate `PoolStateRoot` through `RootPointer.pool_state_root` instead of the hard-coded `POOL_STATE_ROOT_OFFSET` (block 4) in `crates/pool/src/tier.rs`. Acceptance: a pool whose state block is written elsewhere reopens through the root pointer.
- [ ] **POOL4 — Placement-rule evaluator.** `PoolManager::pick_disk` resolves rules in SPECIFICATION-DESIGN§8.3 precedence (Pin > Prefer > Replicate > AutoTier > defaults) instead of the current disk-level pick. Acceptance: one test per precedence level, plus a conflict between two levels resolved by precedence.
- [ ] **POOL5 — Native placement-rules tree.** Persist placement rules as one sorted-run entry per rule keyed `(rule_id, snapshot)` (POOL-DESIGN§1) instead of a single CBOR entry holding the whole list. Acceptance: adding one rule appends one entry; rules round-trip through reopen.
- [ ] **POOL6 — Disk evacuation on removal.** `remove_disk` scans the location table for the disk, re-evaluates placement, migrates extents, and only then marks the disk `Removed` (SPECIFICATION-DESIGN§8.4); today it only marks it `Draining`. Prerequisites: POOL4, [BLOB1](blob-implementation-plan.md), [ENGINE5](engine-implementation-plan.md). Acceptance: removing a disk in a two-disk pool leaves every object readable from the remaining disk.
