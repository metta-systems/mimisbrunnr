# Snapshots — implementation plan

Design: [snapshots-design.md](snapshots-design.md) · Decisions: [snapshots-decisions.md](snapshots-decisions.md) · Order: [operations-plan.md](operations-plan.md)

Prerequisites for the whole scope: [ENGINE3](engine-implementation-plan.md), [METADATA1](metadata-implementation-plan.md), [INDEX13](index-implementation-plan.md), [BLOB2](blob-implementation-plan.md).

- [ ] **SNAPSHOT1 — Snapshot tree.** `SnapshotNode`, ancestor bitmap and skiplist, labels as the value tail (SNAPSHOTS-DESIGN§1.1). Acceptance: a labelled snapshot's label round-trips; ancestry checks agree with a parent walk for 1 000 random pairs.
- [ ] **SNAPSHOT2 — Snapshot-aware key positions.** Thread the snapshot id through every snapshot-aware tree (SNAPSHOTS-DESIGN§1.2).
- [ ] **SNAPSHOT3 — Record versions and history sidecar.** `ObjectRecord.snapshot`; push-down of a frozen-visible version into `ObjectHistory` on the first write after a snapshot; reads at a snapshot by the SNAPSHOTS-DESIGN§1.2 rule; a version keeps the extents and lists its locator names allocated until it goes. Acceptance: write, snapshot, write twice: one `ObjectHistory` entry; the snapshot reads the first version and the head the third; a head read touches no sidecar block (counted).
- [ ] **SNAPSHOT4 — Visibility, retention and rollback.** SNAPSHOTS-DESIGN§1.3, SNAPSHOTS-DESIGN§1.6 (moves update every version naming the extent), SNAPSHOTS-DESIGN§1.7, SNAPSHOTS-DESIGN§1.8 (re-heading the object table by background scan). Acceptance: copy-GC of an extent shared by the head record and a snapshot version leaves both readable; after a rollback the head reads the target snapshot's records before and after the re-head scan completes; switching the head to an ancestor, then forward to a snapshot on the branch it left, then to a sibling branch reads each target's records and terms exactly, and a crash after `SnapshotSwitch` replays to the same head.
- [ ] **SNAPSHOT5 — Snapshot WAL ops.** Emit and replay `SnapshotCreate`, `SnapshotSwitch`, `SnapshotDelete`, `SnapshotUnlink`, `SnapshotDepthUpdate` (currently replay-skipped).
- [ ] **SNAPSHOT6 — Snapshot API and queries.** `DiskEngine::snapshot_create` (currently `NotImplemented`) and `snapshot_switch`, queries with `snapshot_id` compiled against the snapshot's lazily built name maps and run without closure tables, per-object closures at a snapshot computed on demand and cached under a bound (INDEX-DESIGN§2.4), blob reads resolved from the snapshot; the head switch as `brunnr switch --to <label>` (SNAPSHOTS-DESIGN§1.8). Acceptance: end-to-end test creating a snapshot, mutating, and querying the snapshot returns the old graph and old blob bytes ([acceptance scenario](operations-design.md#acceptance-scenarios)); after a rule is installed at the head, a query at the snapshot builds no closure tables and an object's implied tags listed there follow the snapshot's rules, not the head's; a tag renamed at the head is still found by its old name at the snapshot.
