# Cluster sync — implementation plan

Design: [cluster-design.md](cluster-design.md) · Decisions: [cluster-decisions.md](cluster-decisions.md) · Order: [operations-plan.md](operations-plan.md)

Prerequisites for the whole scope: [SNAPSHOT6](snapshots-implementation-plan.md), [RECONCILE2](reconcile-implementation-plan.md).

- [ ] **CLUSTER1 — Peer registry.** `ClusterPeers` tree at `cluster_peers_root` and the peer state machine, with each peer's acknowledged state as CLUSTER-D7 defines it. Prerequisites: CLUSTER-D1, CLUSTER-D7.
- [ ] **CLUSTER9 — Sync bundles from snapshot diffs.** `SyncBundle` built from the direct-state trees with the changes a peer has not seen, skipping blocks by snapshot range (CLUSTER-DESIGN§1), selected as CLUSTER-D7 decides. Prerequisites: CLUSTER1, CLUSTER-D7, [RECONCILE6](reconcile-implementation-plan.md) (snapshot ranges). Acceptance: a bundle after 10 tag changes on a 1 M-object pool holds 10 object deltas and reads only the blocks holding them (counted); a first bundle to an empty peer carries the whole direct state.
- [ ] **CLUSTER2 — Apply and merge.** The receiver journals a bundle's changes as local entries and replays them through the mutation path, merging objects changed on both sides by the rules CLUSTER-D2 selects and collection order by CLUSTER-D6, observing hybrid timestamps. Prerequisites: CLUSTER9, CLUSTER-D2, CLUSTER-D6. Acceptance: concurrent edits of one object's tags on two nodes converge to the same set on both; a subscription on the receiver sees remote changes as events.
- [ ] **CLUSTER4 — Sync modes and bandwidth budget** (SPECIFICATION-DESIGN§10.6, SPECIFICATION-DESIGN§10.8). Prerequisite: CLUSTER9.
- [ ] **CLUSTER5 — Hydration.** Engine support for remote content: the `Remote` content locator and the hydration states CLUSTER-D3 selects (SPECIFICATION-DESIGN§10.3). Prerequisite: CLUSTER-D3.
- [ ] **CLUSTER8 — Ontology by uid.** A bundle carries the ontology records changed between its snapshots, by uid, applied before its other changes; the receiver allocates `TagId`s for tags new to it and reworks postings in the same commit; concurrent edits merge by union of provenance, scalar fields last-writer-wins by hybrid timestamp (ONTOLOGY-DESIGN "Cluster propagation"). Prerequisites: CLUSTER9, [ONTOLOGY11](ontology-implementation-plan.md), [ONTOLOGY15](ontology-implementation-plan.md). Acceptance: two pools whose `TagId`s differ for the same module tag converge on a module install and an ad-hoc tag, and answer the same tag query identically; a module removed on one node and kept by another installer on the other ends with the union of installers.
- [ ] **CLUSTER7 — No local ids on the wire.** Bundles name tags by `TagUid` and terms by value, never by `TagId` or `TermId`; receivers intern them into their own dictionary, and carry no postings or derived terms (cluster-design "Selected design"). Prerequisites: CLUSTER9, [INDEX12](index-implementation-plan.md). Acceptance: two nodes with independently created pools converge on an attribute and both answer the same equality query with the same objects; a rule installed on both derives the same terms without any being shipped.
- [ ] **CLUSTER6 — Multi-node convergence suite.** Two nodes converge while each stays authoritative for its own writes; a node answers a tag query for an object it did not write without fetching blobs ([acceptance scenarios](operations-design.md#acceptance-scenarios); evidence kind `L4`). Prerequisite: CLUSTER2.
