# Journal — implementation plan

Design: [journal-design.md](journal-design.md) · Decisions: [journal-decisions.md](journal-decisions.md) · Order: [operations-plan.md](operations-plan.md)

## Format

- [ ] **JOURNAL8 — Binary payload records.** Every op in JOURNAL-DESIGN§1.3 is written and replayed as its binary record (fixed head, at most one variable part) through hand-written encode/decode in `crates/wal`; `ciborium` leaves `crates/wal` except for `Value` tails, which go through the `crates/types` codec ([INDEX9](index-implementation-plan.md)); the `serde` derives on op payload structs go. Prerequisite: INDEX9 for `SetAttr`. `WalOpKind` takes exactly the values of the JOURNAL-DESIGN§1.3 op-kind table, 0–38 contiguous (`BucketWrite`, `TagBitmapGrow`, `TagBitmapShrink`, `FormatPromote`, `BackpointerInsert` and `BackpointerRemove` go; the chunk-list ops and `ExtendObject` become `AppendPieces`, `ReplacePieces`, `TruncatePieces` and `InsertSharedPieces`, with variable-size `PieceSpec`s). Acceptance: one round-trip test per op kind; decoding an op kind above 38 fails with a defined `WalError`; `AddTag`'s payload is 12 bytes padded to 16; a payload whose length disagrees with its head, or a count or length running past the payload, fails with a defined `WalError`.
- [ ] **JOURNAL9 — Journal buckets and journal sets.** The ring and its A/B `WalHeader` give way to the superblock's journal bucket list (JOURNAL-DESIGN§1.1) and write-once jsets with `JsetHeader`, 8-byte `EntryHead`s, `seq << 16 | index` LSNs and HLC offsets (JOURNAL-DESIGN§1.2); recovery scans the first jset of each bucket and walks valid consecutive sets; trimming frees buckets older than the durable `last_seq`; the `Superblock` struct, `validation/` and `BlockKind`s 3–4 follow. Prerequisites: JOURNAL8, JOURNAL7. Acceptance: a torn write of the last jset loses only that jset's entries; a jset is never rewritten (asserted through a write-tracking test device); recovery after 10 000 commits across several buckets reproduces the engine state; an `AddTag` entry occupies 24 bytes.
- [ ] **JOURNAL7 — One checksum algorithm.** Jsets, blocks, regions, sorted runs, root pointers and superblocks all use the algorithm OPERATIONS-D4 selects, through one `no_std` implementation; `crc32fast` goes, and so does `crc32c` if it is not the selected implementation. Prerequisite: OPERATIONS-D4. Acceptance: one checksum function in `crates/`; a flipped byte in each checksummed structure fails with its crate's defined error.

## Commits and checkpoints

- [ ] **JOURNAL10 — Group commit and durability levels.** `Sync` and `Buffered { max_delay }` on every mutating call; adaptive sealing (idle immediate, batching under load, 256 KiB cap); several jsets in flight, acknowledged in sequence; FUA writes where the `BlockDevice` offers them, otherwise one flush per commit (JOURNAL-DESIGN§1.5). Prerequisite: JOURNAL9. Acceptance: one `Sync` call on an idle pool issues one jset write and one barrier; 1 000 concurrent `Sync` callers share a few jsets; a `Buffered` mutation is durable within its bound with the host driver running.
- [ ] **JOURNAL11 — One barrier per commit with extent verification.** Entries referencing new extents carry `extent_sum`; a commit issues data writes, jset write and one barrier; recovery verifies the extents named by the tail's entries and drops a commit whose data failed (JOURNAL-DESIGN§1.5). Prerequisites: JOURNAL10, [BLOB1](blob-implementation-plan.md). Acceptance: with a test device that drops the data write but keeps the jset, recovery leaves the object at its previous state and the rest of the pool intact; a normal commit issues exactly one barrier.
- [ ] **JOURNAL12 — Root in the journal.** A checkpoint is a `Checkpoint` entry with the new root list; the superblock's checkpoint hint is written only on clean unmount and on journal bucket-list changes; mount reads the hinted jset and takes the newest checkpoint found (ENGINE-DESIGN§1.2). Prerequisites: JOURNAL9, [ENGINE3](engine-implementation-plan.md). Acceptance: 100 checkpoints cause no superblock write; a crash after a checkpoint mounts at that checkpoint; a clean unmount mounts without scanning the journal tail.
- [ ] **JOURNAL2 — Trim respects pins.** The trim point recorded in `last_seq` is the lowest of the newest checkpoint, the lowest live `lsn_min` and retained history (JOURNAL-DESIGN§1.4). Prerequisite: JOURNAL9. Acceptance: push an entry without flushing its node, checkpoint, the jset holding it is not freed.
- [ ] **JOURNAL4 — Checkpoint cadence driver.** The engine exposes a `checkpoint` extracted from `commit` and a non-blocking query of what is due — journal fill in the background or aggressive band, dirty bytes > 8 MiB, 30 s since the last checkpoint, or a `Buffered` deadline, against a caller-supplied clock — implementing the JOURNAL-DESIGN§1.4 fill-level bands; mutations go to the journal plus in-memory nodes only. The engine starts no thread: the embedder runs the driver (on the host a `std`-gated helper that spawns a thread around those calls; on Vesper the filesystem server's own thread or event loop), and a mutation entering the stall band returns a defined error or checkpoints inline rather than waiting on a thread it does not own. Prerequisites: [ENGINE1](engine-implementation-plan.md), JOURNAL10. Acceptance: with the host helper running, 10 000 mutations without `commit()` are checkpointed within 30 s, and pumping the journal into the aggressive band wakes it immediately; without any driver, the due-query reports the overdue checkpoint and a manual `checkpoint` call clears it.

- [ ] **JOURNAL14 — Object lifecycle ops.** `CreateObject` carries the initial `state` (`Active` or `Writing`); `FinalizeObject` replaces `ChunkObjectFinalize` and closes streams, piece writes and re-cuts (JOURNAL-DESIGN§1.3). Prerequisite: JOURNAL8. Acceptance: fixed expected bytes for both payloads; replaying `CreateObject` with each state yields that state; an `Active` piece write killed before `FinalizeObject` shows no content.

## History and mirroring

- [ ] **JOURNAL13 — Optional retained history.** Journal buckets are kept past the trim point within per-pool byte and age caps (default none); a reader iterates retained entries from an LSN (JOURNAL-DESIGN§1.6). Prerequisite: JOURNAL2. Acceptance: with a cap set, entries within it are readable after reopen and buckets beyond it are freed; with the default, buckets are freed as soon as the trim point passes them; no subscription state changes the trim point.
- [ ] **JOURNAL6 — Journal mirroring across hot disks.** Prerequisite: JOURNAL-D1.

## Payload transforms

- [ ] **JOURNAL5 — Compressed journal sets.** `JSET_FLAG_COMPRESSED` on write and replay, compressing the set's entries as one unit before encryption, with the algorithm BLOB-D3 selects. Prerequisites: JOURNAL9, [BLOB-D3](blob-decisions.md). Acceptance: compressed sets round-trip through replay; a set that would not shrink is written uncompressed.

Encrypted journal sets: [ENCRYPTION3](encryption-implementation-plan.md).
