# Unix interoperability and FUSE — implementation plan

Design: [unix-design.md](unix-design.md) · Decisions: [unix-decisions.md](unix-decisions.md) · Order: [operations-plan.md](operations-plan.md)

- [ ] **UNIX1 — Projections from the index.** Path resolution, directory listing and name search go through the hierarchical `unix-path` key and the context term (UNIX-DESIGN "Selected design"); `PathContextManager`, its boot-time rebuild, `PathProjection::reverse_lookup`'s scan and `path_contexts_bytes` in the legacy blob go. Prerequisites: [INDEX18](index-implementation-plan.md), [INDEX19](index-implementation-plan.md). Acceptance: import a tree, commit, reopen: `/ctx/` lists the same paths with nothing rebuilt at mount; resolving a path reads a number of blocks that does not grow with the number of projected paths (counted). Unblocks [ENGINE8](engine-implementation-plan.md).
- [ ] **UNIX2 — FUSE write operations.** Prerequisite: UNIX-D1.
- [ ] **UNIX3 — Real file attributes.** `getattr` reports `mtime`, `ctime` and size from the object record and mode, uid and gid from the scoped-or-unscoped `unix-*` values (UNIX-DESIGN "Selected design"), with the defaults UNIX-D2 selects. Prerequisites: UNIX-D2, [METADATA7](metadata-implementation-plan.md).
- [ ] **UNIX4 — Symlinks under `/ctx/`.** Model `ImportKind::Symlink` in `VfsEntryKind`. Prerequisites: UNIX-D1, UNIX-D3.
- [ ] **UNIX5 — FUSE mount integration tests.** A test target that mounts, lists and reads through FUSE where the host allows unprivileged mounts (`user_allow_other`), skipped with a reported reason elsewhere.
- [ ] **UNIX8 — Scoped value validation.** Setting an attribute checks a `Scoped` value's inner value against the tag's `value_type` and requires the scope to be a term of a grouping-, ordered- or ranked-flavoured key; failures are a defined engine error. Prerequisite: [ONTOLOGY16](ontology-implementation-plan.md). Acceptance: `unix-mode = Scoped(ctx, Text("x"))` and a scope naming a plain label are rejected; `unix-path = Scoped(ctx, Text("/a"))` is accepted.
- [ ] **UNIX9 — Archive export.** `mimir project export <ctx> --format …` writes the context as an archive: ordered manifest, virtual directories first, one file per object at its first path and hardlinks at the rest, scoped-or-default mode/uid/gid (UNIX-DESIGN "Export"). Prerequisites: UNIX-D3, UNIX-D4. Acceptance: export a context holding an object with two paths; the archive lists both directories, one file and one hardlink with the expected modes.
- [ ] **UNIX10 — Content import.** `mimir project import` reads file contents into blobs, reuses an existing object when the BLAKE3 content hash matches (as METADATA-D6 selects), sets the context membership with the scoped path, mode, uid and gid, and reports created and deduplicated counts; `--auto-tag` asserts the unix-interop module's path-convention categories (`lang`, `type`). Prerequisites: [BLOB1](blob-implementation-plan.md), UNIX-D4, [METADATA-D6](metadata-decisions.md). Acceptance: importing a tree containing two identical files creates one object with two scoped paths.
