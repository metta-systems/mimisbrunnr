# Unix interoperability and FUSE — implementation plan

Design: [unix-design.md](unix-design.md) · Decisions: [unix-decisions.md](unix-decisions.md) · Order: [operations-plan.md](operations-plan.md)

- [ ] **UNIX1 — Rebuild path contexts at boot.** `DiskEngine::open` scans the forward index for `Attr(unix-path, …)` and rebuilds `PathContextManager`; `path_contexts_bytes` leaves the legacy blob. Acceptance: import a tree, commit, reopen: `/ctx/` lists the same paths. Unblocks [ENGINE8](engine-implementation-plan.md).
- [ ] **UNIX2 — FUSE write operations.** Prerequisite: UNIX-D1.
- [ ] **UNIX3 — Real file attributes.** Prerequisite: UNIX-D2.
- [ ] **UNIX4 — Symlinks under `/ctx/`.** Model `ImportKind::Symlink` in `VfsEntryKind`. Prerequisite: UNIX-D1.
- [ ] **UNIX5 — FUSE mount integration tests.** A test target that mounts, lists and reads through FUSE where the host allows unprivileged mounts (`user_allow_other`), skipped with a reported reason elsewhere.
- [ ] **UNIX6 — Path lookup without a scan.** `PathProjection::reverse_lookup` resolves a path through an index on the path-projection attribute (UNIX-DESIGN§1) instead of scanning every projected path. Acceptance: lookup cost does not grow with the number of projected paths (benchmark or operation count).
- [ ] **UNIX8 — Scoped value validation.** Setting an attribute checks a `Scoped` value's inner value against the tag's `value_type` and requires the scope to be a term of a grouping-, ordered- or ranked-flavoured key; failures are a defined engine error. Prerequisite: [ONTOLOGY16](ontology-implementation-plan.md). Acceptance: `unix-mode = Scoped(ctx, Text("x"))` and a scope naming a plain label are rejected; `unix-path = Scoped(ctx, Text("/a"))` is accepted.
- [ ] **UNIX9 — Archive export.** `mimir project export <ctx> --format …` writes the context as an archive: ordered manifest, virtual directories first, one file per object at its first path and hardlinks at the rest, scoped-or-default mode/uid/gid (UNIX-DESIGN "Export"). Prerequisites: UNIX-D3, UNIX-D4. Acceptance: export a context holding an object with two paths; the archive lists both directories, one file and one hardlink with the expected modes.
- [ ] **UNIX10 — Content import.** `mimir project import` reads file contents into blobs, reuses an existing object when the BLAKE3 content hash matches, sets scoped path, mode, uid and gid, and reports created and deduplicated counts; `--auto-tag` adds convention tags. Prerequisites: [BLOB1](blob-implementation-plan.md), UNIX-D4. Acceptance: importing a tree containing two identical files creates one object with two scoped paths.
