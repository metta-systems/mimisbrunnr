# Ontology — implementation plan

Design: [ontology-design.md](ontology-design.md) · Decisions: [ontology-decisions.md](ontology-decisions.md) · Order: [operations-plan.md](operations-plan.md)

- [ ] **ONTOLOGY1 — Single tag-id allocator.** Drop `Engine.next_tag_id`; `Engine::register_tag` goes through `OntologyState::install`; `next_tag_id` derivation lives in `OntologyState`. Prerequisite: ONTOLOGY-D1. Acceptance: tags registered ad hoc and through modules never collide across reopen; the legacy blob's `next_tag_id` is unused ([ENGINE7](engine-implementation-plan.md)).
- [ ] **ONTOLOGY2 — `OntologyError::Storage`.** Add `Storage(#[from] StorageError)` and replace the lossy mapping of region errors into `OntologyError::Cbor`. Acceptance: a region-full failure surfaces as the storage variant in a test.
- [ ] **ONTOLOGY3 — Adopt orphan tags.** `OntologyState::adopt_orphan` and `mimir ontology adopt <tag> --into <module>`. Prerequisite: ONTOLOGY-D1.
- [ ] **ONTOLOGY4 — Module syntax migration.** Prerequisite: ONTOLOGY-D2 selecting a change.
- [ ] **ONTOLOGY5 — Tag conflict check on install.** Installing a module that declares an existing tag name with different semantics or attribute value type fails with an `OntologyError` naming the tag, both modules and both semantics; identical declarations stay shared. Acceptance: a test installs two modules declaring `bpm` as `attribute(int)` and `label`, expects the error and an unchanged ontology.
- [ ] **ONTOLOGY6 — Rematerialise on new implications.** When install or upgrade adds `A → B`, the engine adds `B` and its ancestors to every object tagged `A`: tag bitmaps and `TagOrigin::Materialized` forward-index assertions, WAL-logged like other tag mutations. Acceptance: tag 3 objects `flac`, install `flac → audio`, query `audio` returns them, also after reopen.
- [ ] **ONTOLOGY7 — De-materialise on removed implications.** Removing `A → B` (upgrade or module removal) removes `B` only from objects with no other source of it (ONTOLOGY-DESIGN "Upgrade"). Prerequisite: ONTOLOGY6. Acceptance: an object tagged `flac` and `mp3` keeps `audio` after `flac → audio` is removed; one tagged only `flac` loses it; a directly tagged `audio` object keeps it.
- [ ] **ONTOLOGY8 — Upgrade with blocked changes.** Upgrade removes tags no object carries, reports blocked removals with object counts and semantics changes as migration plans, and applies them only with `--force`. Prerequisites: ONTOLOGY7, ONTOLOGY-D6.
- [ ] **ONTOLOGY9 — Scrub policies.** Module removal takes a policy: Preserve (default; tags become orphans), RemoveUnique (today's `OntologyState::scrub`, plus removing the tags from objects), Purge. Prerequisites: ONTOLOGY7, ONTOLOGY-D1 (orphan representation), ONTOLOGY-D6. Acceptance: one test per policy checks the ontology and the tagged objects after reopen.
