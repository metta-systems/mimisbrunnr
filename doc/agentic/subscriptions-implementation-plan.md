# Subscriptions — implementation plan

Design: [subscriptions-design.md](subscriptions-design.md) · Decisions: [subscriptions-decisions.md](subscriptions-decisions.md) · Order: [operations-plan.md](operations-plan.md)

## Persistence

- [ ] **SUBSCRIPTION7 — Positional, versioned `SubscriptionRecord`; ids from the id counter.** The record as SUBSCRIPTIONS-DESIGN§1 pins it (array, schema version first, the stored query form through QUERY11, `cursor_ns`), keyed by id alone with no snapshot field; ids from the `Subscription` id counter (ENGINE-DESIGN§1.2), replacing the `next_id` derived at boot. Prerequisites: [QUERY11](query-implementation-plan.md), [ENGINE7](engine-implementation-plan.md). Acceptance: a record round-trips through reopen; a newer version fails with a defined `WatchError`; a record missing a trailing field reads with its documented default; removing the newest subscription and reopening gives the next subscription a larger id.
- [ ] **SUBSCRIPTION1 — Membership containers.** The inline `cached_result: Vec<u8>` gives way to the `SubscriptionMembers` tree of posting containers keyed `(id, high)` (SUBSCRIPTIONS-DESIGN§1). Prerequisites: [ALLOCATION1](allocation-implementation-plan.md), [INDEX13](index-implementation-plan.md). Acceptance: a subscription over 100 000 objects round-trips its membership; an ack touching one window rewrites one container; a snapshot rollback leaves membership and cursor unchanged.
- [ ] **SUBSCRIPTION2 — Per-subscription copy-on-write.** With append-on-flush, mutating one subscription appends a one-entry run. Prerequisite: [ENGINE1](engine-implementation-plan.md). Acceptance: 1 000 subscriptions, mutate one, only that entry's bytes change on disk.

## Live behaviour

- [ ] **SUBSCRIPTION3 — The match index.** `term_to_watchers`, `key_to_watchers`, `content_watchers` and `unresolved` built from the compiled queries of subscriptions and of placement and hydration rules ([QUERY14](query-implementation-plan.md)); mutations reach watchers through the closure delta and evaluate them with `matches` ([QUERY16](query-implementation-plan.md)); a reached subscription stores events, a reached rule whose match changed enqueues reconcile work; rule rework hands container deltas to the subscriptions of the reworked terms; names that do not resolve yet wait in `unresolved` until interning or an install resolves them, and reclamation returns them there (SUBSCRIPTIONS-DESIGN "Evaluation"). Acceptance also: a subscription on `artist = "Nobody"` made before any object has that value gets `Entered` for the first object given it; after that value is reclaimed and written again, it still does; a subscription naming a tag of an uninstalled module starts matching when the module is installed. Prerequisites: QUERY14, [INDEX14](index-implementation-plan.md). Acceptance: tagging an object `flac` delivers `Entered` to a subscription on `audio`; setting `mime = audio/flac` does too; installing `m4a → audio` delivers `Entered` for every existing `m4a` object; an evaluation reads no posting container (counted).
- [ ] **SUBSCRIPTION8 — Pending events, poll and acknowledge.** The `SubscriptionEvents` tree with `PendingEvent` entries and bulk window entries (SUBSCRIPTIONS-DESIGN§1), inserted with the mutation and re-created by replay; `poll(sub, max)` in key order; `ack(lsn)` removing the range, applying it to the membership and persisting cursor and `cursor_ns` as one `SubscriptionAck`; subscription create, change and removal as `SubscriptionPut` / `SubscriptionDelete` (JOURNAL-DESIGN§1.3); overflow past the `retention` bound (SUBSCRIPTIONS-DESIGN "Delivery"). Prerequisites: SUBSCRIPTION1, SUBSCRIPTION3. Acceptance: a crash between `poll` and `ack` redelivers the same events with the same LSNs; after a restart, a dormant subscription's events come back in commit order with no journal history retained; a rule install entering 1 M objects writes one entry per window; exceeding the bound marks the subscription `Overflowed` and its next poll is the diff.
- [ ] **SUBSCRIPTION4 — Debounce in `step`.** The engine's `step` releases events whose debounce window elapsed ([ENGINE13](engine-implementation-plan.md)); `tick` goes. Prerequisite: SUBSCRIPTION8.
- [ ] **SUBSCRIPTION5 — `mimir watch stream`.** Prerequisites: SUBSCRIPTION-D1, SUBSCRIPTION8.
- [ ] **SUBSCRIPTION6 — Overflow catch-up.** The result-set diff of an overflowed subscription against its membership at the cursor, with content and description changes detected by `modified_ns` against `cursor_ns`, after which the subscription resumes (SUBSCRIPTIONS-DESIGN "Offline catch-up"). Prerequisites: SUBSCRIPTION8, [METADATA7](metadata-implementation-plan.md). A head switch overflows every subscription with `switched_to` set; its next poll returns `HeadSwitched` then an `Entered`/`Exited`/`ContentChanged` diff (SUBSCRIPTIONS-DESIGN "Delivery"). Acceptance: an overflowed subscription reports `Entered`, `Exited`, `Created`, `Deleted` and `ContentChanged` that match a hand-computed diff; after switching the head back to a snapshot, then forward to a later one, then to a sibling branch, each poll starts with `HeadSwitched` and its diff matches the query evaluated at the new head.
