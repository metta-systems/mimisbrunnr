# Subscriptions — implementation plan

Design: [subscriptions-design.md](subscriptions-design.md) · Decisions: [subscriptions-decisions.md](subscriptions-decisions.md) · Order: [operations-plan.md](operations-plan.md)

## Persistence

- [ ] **SUBSCRIPTION7 — Positional, versioned `SubscriptionRecord`; ids by high-water marker.** The record as SUBSCRIPTIONS-DESIGN§1 pins it (array, schema version first, the stored query form through QUERY11, `cursor_ns`), keyed by id alone with no snapshot field; removing the largest id leaves a high-water marker. Prerequisite: [QUERY11](query-implementation-plan.md). Acceptance: a record round-trips through reopen; a newer version fails with a defined `WatchError`; a record missing a trailing field reads with its documented default; removing the newest subscription and reopening gives the next subscription a larger id.
- [ ] **SUBSCRIPTION1 — Membership containers.** The inline `cached_result: Vec<u8>` gives way to the `SubscriptionMembers` tree of posting containers keyed `(id, high)` (SUBSCRIPTIONS-DESIGN§1). Prerequisites: [ALLOCATION1](allocation-implementation-plan.md), [INDEX13](index-implementation-plan.md). Acceptance: a subscription over 100 000 objects round-trips its membership; an ack touching one window rewrites one container; a snapshot rollback leaves membership and cursor unchanged.
- [ ] **SUBSCRIPTION2 — Per-subscription copy-on-write.** With append-on-flush, mutating one subscription appends a one-entry run. Prerequisite: [ENGINE1](engine-implementation-plan.md). Acceptance: 1 000 subscriptions, mutate one, only that entry's bytes change on disk.

## Live behaviour

- [ ] **SUBSCRIPTION3 — Term-indexed evaluation.** `term_to_subs`, `key_to_subs` and `content_subs` built from compiled queries ([QUERY14](query-implementation-plan.md)); mutations reach subscriptions through the closure delta and evaluate them against the object's own terms; rule rework hands container deltas to the subscriptions of the reworked terms (SUBSCRIPTIONS-DESIGN "Evaluation"). Prerequisites: QUERY14, [INDEX14](index-implementation-plan.md). Acceptance: tagging an object `flac` delivers `Entered` to a subscription on `audio`; setting `mime = audio/flac` does too; installing `m4a → audio` delivers `Entered` for every existing `m4a` object; an evaluation reads no posting container (counted).
- [ ] **SUBSCRIPTION8 — Poll and acknowledge.** `poll(sub, max)` from the in-memory buffer, `ack(lsn)` persisting cursor and `cursor_ns`; what happens after a restart or buffer overflow follows SUBSCRIPTION-D6 (SUBSCRIPTIONS-DESIGN "Delivery"). Prerequisites: SUBSCRIPTION1, SUBSCRIPTION3, SUBSCRIPTION-D6. Acceptance: a crash between `poll` and `ack` redelivers the polled events with the same LSNs; events after a restart match what SUBSCRIPTION-D6 selects.
- [ ] **SUBSCRIPTION4 — Debounce in `step`.** The engine's `step` releases events whose debounce window elapsed ([ENGINE13](engine-implementation-plan.md)); `tick` goes. Prerequisite: SUBSCRIPTION8.
- [ ] **SUBSCRIPTION5 — `mimir watch stream`.** Prerequisites: SUBSCRIPTION-D1, SUBSCRIPTION8.
- [ ] **SUBSCRIPTION6 — Offline catch-up.** Replay from the cursor through the retained journal, falling back beyond it to the result-set diff against the stored membership, with content and description changes detected by `modified_ns` against `cursor_ns` (SUBSCRIPTIONS-DESIGN "Offline catch-up"). Prerequisites: SUBSCRIPTION8, [JOURNAL13](journal-implementation-plan.md), [METADATA7](metadata-implementation-plan.md). Acceptance: a dormant subscription past the retained journal reports `Entered`, `Exited`, `Created`, `Deleted` and `ContentChanged` that match a hand-computed diff.
