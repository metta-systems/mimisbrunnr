# B+ tree regions — implementation plan

Design: [btree-design.md](btree-design.md) · Decisions: [btree-decisions.md](btree-decisions.md) · Order: [operations-plan.md](operations-plan.md)

## Region format

- [ ] **BTREE9 — Write-once regions, block-addressable runs, one run format.** `BtreeNodeHeader` (64 B, `BREG` preamble) with its checksum written once in block 0; runs of an index block (`RunHeader`, `KeyFormat`, `RunBlockEntry`s, fence keys) and self-contained data blocks with 8-aligned values, large values in value blocks (`LargeValueRef`) and the whiteout entry flag (BTREE-DESIGN§1.1–1.2, BTREE-DESIGN§1.6); byte-width frame-of-reference keys replace the bit-packed codec; every checksum slot is 64-bit, filled by `checksum64`. A new block-level region layer replaces `BtreeRegion::write_full`, `append_sorted_run`, the `*_packed` calls and whole-node `LoadedNode` loads: create a region, append a run, look a key up reading the cached index block and one data block per run, iterate a key range, and load stops at the first invalid index block. Every tree persisting through regions moves to it in the same slice, and CBOR-valued trees (ontology, subscriptions, placement rules) store their CBOR as opaque values in the same runs — the CBOR run kind and `StorageError::MixedRunFormats` go. `RUN_FLAG_ENCRYPTED` is never set, and a run carrying it fails with a defined error until runs are encrypted ([ENCRYPTION-D6](encryption-decisions.md)). `FormatPromote` and its handling go from `crates/journal` and `crates/storage`. Acceptance: fixed expected bytes for a header block, an index block and a data block; a lookup in a 3-run node reads at most one data block per run (counted); a value of 8 KiB is read in place 8-byte aligned; a run torn in its last data block is dropped at load and earlier runs read back; an ontology tree and a postings tree are read through the same region reader; a run with `RUN_FLAG_ENCRYPTED` fails with the defined error; every existing persistence round-trip test passes through the new layer.
- [ ] **BTREE10 — Positional page regions.** Radix leaves and inner nodes and forward overflow as `logical_pages` pages written in page runs; backward-linked chains (BTREE-DESIGN§1.7). Prerequisite: BTREE9. Acceptance: changing one record of a full radix leaf writes 8 KiB; a never-written page reads as zeros; a chain of three regions is appended without rewriting the first two.

## Live tree machinery

- [ ] **BTREE4 — Separator keys for descent.** Inner nodes route by full separator keys with `NodePtr` values; descent checks that a loaded child's first key is not below its separator and reports corruption otherwise. Prerequisite: BTREE9. Acceptance: a tree of term-dictionary keys (wider than 16 bytes) and one of chunk hashes descend correctly across three levels.
- [ ] **BTREE5 — Append-on-flush with whiteouts.** A flush writes one new run with the pending inserts and whiteouts at the region's next free block and writes nothing else. Prerequisite: BTREE9. Acceptance: 1 000-entry tree, modify one entry, flush: the region grows by one index block and one data block; a delete survives flush and reopen.
- [ ] **BTREE7 — Compaction.** Compaction (more than 4 runs, more than 75 % of blocks, or no room for the next run) merges into a fresh region, splitting when needed, and the parent's pointer follows at the next checkpoint (BTREE-DESIGN§1.4). Engine hook: [ENGINE2](engine-implementation-plan.md). Acceptance: after compaction the node has one run; a crash between compaction and checkpoint reopens on the old region with no data lost.
